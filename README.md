# edge-frontier

AI 活用の**やり方**を常識外の強度・範囲まで押し進めている事例（スーパーエッジケース）を集めて解説し、そこから学びを抽出する記録です。学術研究ではなく、実践者の収集と思索です。規模の大きさ（トークン量・費用・並列数）はエッジの症状であって定義ではありません。面白いのは常に「どうやって・なぜそうしたか・何が起きたか」の方にあります。

主な読者は著者本人で、自分の運用に移植できる手筋と、どこまでやってよいかという強度の相場観を事例から得るために続けています。誰でも読めるように公開しています。動かすものはなく、[cases.md](cases.md) の台帳を読めば足ります。事例とその解説は台帳のメモ欄にあり、発見日が 2026-08-24 以降の行では学びを「盗める手筋」（自分の運用にそのまま移せるやり方）として書き出しています。関連する論考は [reading-list.md](reading-list.md) にあります。事例を物語として解説するレポートは著者の Obsidian vault に出していて、この repo には含まれません。

例えば台帳の 1 件目は、月 $200 の Claude Max 1 契約で 7 体の agent に複数事業を運営させ、1 体に独自メールアドレスと成約までの全権を与えた結果、3 週間・コールドメール 240 通・売上 $0 で撤退した記録です。2026-08-25 の行には、14 の SaaS 製品を 1 人で運営し、agent には backlog への起票までをさせて人間の承認後に実行する事例が並び、その「盗める手筋」は全権でなく提案までで止める線の引き方です。

台帳の行は AI が書いています。観測の主な流入元は [daily-research](https://github.com/shimo4228/daily-research) の `edge` line（Claude Code が外部を調べて書くレポート）で、台帳への取り込みも Claude Code が行います。2026-08-22 の取り込みからは、別プロセスの fact-checker agent が追記を一次 URL と照合し、不正確な主張が 1 件でもあれば commit せず人間へ回します。これまでは人間が一次ソースに合わせて行を直してから commit しています（最初の 6 行、2026-08-20 と 2026-08-21 の取り込み分はこの照合の導入前です）。確かめられなかった主張は落とさずに載せます（扱いは「[観測ループ](#観測ループ)」）。

## 3 本柱（初期の見取り図）

| 柱 | 何を観測するか | 置き場 |
|---|---|---|
| 突破系（成功エッジ） | AI だけで会社・製品を回す、1 人 + agent 群で組織相当の成果を出す、常識外の workflow の発明など、やり方が常識外で成功している事例 | [cases.md](cases.md) |
| 崩壊系（失敗エッジ） | やりすぎの果ての failure mode — 技能退化、AI 依存の破綻、極端運用が壊れた事後検証（post-mortem） | [cases.md](cases.md) |
| 生活・認知系エッジ | 開発以外の極端活用 — 生活の意思決定・人間関係・思考の全面 AI 委譲と、それによる人間側の変容の記録 | [cases.md](cases.md) |

台帳ではこの 3 本柱に加えて、順位表や予算消化の圧力が端を作り出した事例を「境界例（製造された端）」として記録しています。台帳の「型」欄にはこの 4 つ（突破・崩壊・生活認知・境界例）が入り、1 つの事例が 2 つの型にまたがるときは「突破+崩壊」のように併記します。

## 入場条件と境界

冒頭に書いた目的（手筋と相場観を事例から得ること）のため、採否の中心はこの一問です。**手筋か相場観が盗めるか。迷ったら載せる**（偽陰性のほうが偽陽性より高くつくためです。台帳に載せる時点の確認は一次 URL との照合までで、手筋を自分の運用に取り入れるときに必要に応じて検証を重ねれば足ります）。下の項目は、この一問と並べて当てる範囲の境界です。

- **規模の大きさ単独はエッジではありません**。やり方が常識外で、手筋が具体的に読めることを求めます。一人称は優先しますが必須ではありません。三人称・二次経由でも手筋が読めれば載せ、未検証の主張には `[unverified]` を付けて載せます
- **自然発生の端**（実践者が自分の目的で強度を上げた結果）を優先し、**製造された端**（順位表・予算消化圧・ネタ作りが端を目的化させたもの）を載せる場合はその旨を明記します
- **崩壊系は限界値の観測**として集めます。どのパラメータをどこまで上げたら何が壊れたか、および突破事例の中の壊れかけ徴候を拾います。post-mortem の公開を待つ受動収集はしません
- **[desire-frontier](https://github.com/shimo4228/desire-frontier) との境界**: desire は「AI に頼みたいことが尽きた後」の需要側（欲望・虚無）を観測します。edge は「常識外のやり方」でいま起きていることとその学びを扱います。崩壊系の証言が枯渇型（頼みたいことが尽きた）なら desire-frontier の証言の記録へ回します
- 新ツールの**紹介一般**は対象外ですが、ツールが**常識外の使い方**をされている事例は対象です。平均的な活用 Tips への劣化はしません。ベンチマーク・有名事例の再確認（裏付け）も成果とは数えません

## 観測ループ

daily-research の `edge` line が、毎朝いくつかの観測ラインを順番に回す daily-research の輪番の中で、この repo を作業ディレクトリにして外部を観測し、事例を物語として解説するレポートを Obsidian vault へ出します。レポートの必須節「盗める手筋」は、取り込みのときに 1 行に要約されて [cases.md](cases.md) のメモ欄に入ります。

発見の台帳への還元（[cases.md](cases.md) / [reading-list.md](reading-list.md)）は [`scripts/ingest.sh`](scripts/ingest.sh) が行います。取り込みは既存の入場条件と型（上の 4 つ）を**適用するだけ**で、型の新設・入場条件の変更・既存行の書き換えはしません。確かめられない主張の扱いは 2 段です。取り込みの時点で確かめられなかった主張には `[unverified]` が付きます。fact-checker が URL に届かない・有料壁・本文に該当箇所がない、といった理由で確かめられなかった主張は不合格にせず、タグを付けないまま commit し、commit message に列挙します。commit は自動で、push は人間が行います。手順は [`scripts/ingest-protocol.md`](scripts/ingest-protocol.md) と [`scripts/factcheck-protocol.md`](scripts/factcheck-protocol.md) にあります。規準そのもの（型の再編・README）の見直しは、人間が事例の蓄積を見て行います。

## この構造は足場である

型分類（3 本柱と境界例）と入場条件・境界は初期の見取り図で、事例が溜まって実態と合わなくなったら構造の方を溶かします。

Status: 2026-08-20 に開始しました。上の観測ループは仕組みの説明で、2026-10-10 時点でこの repo にある最後の取り込みの commit は 2026-08-29 です。器（DOI 化・essay 化など）は素材が溜まってから決めます。
