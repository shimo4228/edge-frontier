# edge-frontier

AI 活用の**やり方**を常識外の強度・範囲まで push している事例 — スーパーエッジケース — を集めて解説し、そこから学びを抽出する記録。学術研究ではなく、実践者の収集と思索。規模の大きさ(トークン量・費用・並列数)はエッジの症状であって定義ではない — 面白いのは常に「どうやって・なぜそうしたか・何が起きたか」の方にある。

観測の主流入は daily-research の `edge` line(毎日実行)。

## 3 本柱(初期の見取り図)

| 柱 | 何を観測するか | 置き場 |
|---|---|---|
| 突破系(成功エッジ) | AI だけで会社・製品を回す、1 人 + agent 群で組織相当の output を出す、常識外の workflow の発明など、やり方が常識外で成果を出している一人称事例 | cases.md |
| 崩壊系(失敗エッジ) | やりすぎの果ての failure mode — 技能退化、AI 依存の破綻、極端運用が壊れた事後検証(post-mortem) | cases.md |
| 生活・認知系エッジ | 開発以外の極端活用 — 生活の意思決定・人間関係・思考の全面 AI 委譲と、それによる人間側の変容の一人称記録 | cases.md |

## 入場条件と境界(2026-08-27 改訂。ここが正本 — daily-research の config focus はこの要約)

この repo の目的は**アイデア収穫**である: 読者(著者本人)が事例から、自分の運用に移植
できる**手筋**と、強度の**相場観**(ここまでやっていいのかという上限の更新)を得る。
採否はこの一問で決める — **手筋か相場観が盗めるか。迷ったら載せる**(偽陰性のほうが
偽陽性より高くつく。検証は採用時に on-demand で行えばよい)。

- **規模の大きさ単独はエッジではない**。how が常識外で、手筋が具体的に読めること。
  一人称は優先だが必須ではない — 三人称・二次経由でも手筋が読めれば載せ、未検証の
  主張は `[unverified]` を付けて載せる
- **自然発生の端**(実践者が自分の目的で強度を上げた結果)を優先し、**製造された端**
  (順位表・予算消化圧・ネタ作りが端を目的化させたもの)は載せる場合その旨を明記する
- **崩壊系は限界値の観測**として集める: どのパラメータをどこまで上げたら何が壊れたか、
  および突破事例の中の壊れかけ徴候。post-mortem の公開を待つ受動収集はしない
- **desire-frontier との境界**: desire は「AI に頼みたいことが尽きた後」の需要側(欲望・虚無)を観測する。edge は「常識外のやり方」でいま起きていることとその学びを扱う。崩壊系の証言が枯渇型(頼みたいことが尽きた)なら desire-frontier の testimonies へ回す
- 新ツールの**紹介一般**は対象外だが、ツールが**常識外の使い方**をされている事例は対象。
  平均的な活用 Tips への劣化は禁止。ベンチマーク・有名事例の再確認(裏付け)も成果ではない

## 観測ループ

daily-research の `edge` line が毎日(daily = true、daily-research ADR-0013)この repo を cwd に外部観測し、事例を物語として解説するレポートを Obsidian vault へ出す。レポートの節構成は「何が起きたか(物語)/盗める手筋(必須)/検証メモ」+ 固定 2 節(機会メモ/ソース)で、正本は daily-research の `templates/report-template-edge.md`(2026-08-27〜)。発見の台帳への還元(cases.md / reading-list.md)は `scripts/ingest.sh` が毎朝自動で行う(launchd `com.shimomoto.edge-ingest.plist`、2026-08-21〜)。ingest は既存の入場条件と型を**適用するだけ**の run で、型の新設・入場条件の変更・既存行の書き換えは行わず、追記のみを、別プロセスの fact-checker agent が追加行の事実主張を一次 URL と照合して pass した場合だけ commit する(削除行がある・検証 fail・検証パス不能のいずれも commit せず人間へ回す)。収まらない事例は commit message の「候補」節に残り、規準そのものの見直し(型の再編・README)は人間が事例の蓄積を見て行う。push も人間。良い事例が無い日は「なし」と短く書いてよい(発見ノルマなし)。
