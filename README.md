# edge-frontier

AI 活用の**やり方**を常識外の強度・範囲まで push している事例 — スーパーエッジケース — を集めて解説し、そこから学びを抽出する記録。学術研究ではなく、実践者の収集と思索。規模の大きさ(トークン量・費用・並列数)はエッジの症状であって定義ではない — 面白いのは常に「どうやって・なぜそうしたか・何が起きたか」の方にある。

観測の主流入は daily-research の `edge` line(毎日実行)。

## 3 本柱(初期の見取り図)

| 柱 | 何を観測するか | 置き場 |
|---|---|---|
| 突破系(成功エッジ) | AI だけで会社・製品を回す、1 人 + agent 群で組織相当の output を出す、常識外の workflow の発明など、やり方が常識外で成果を出している一人称事例 | cases.md |
| 崩壊系(失敗エッジ) | やりすぎの果ての failure mode — 技能退化、AI 依存の破綻、極端運用が壊れた事後検証(post-mortem) | cases.md |
| 生活・認知系エッジ | 開発以外の極端活用 — 生活の意思決定・人間関係・思考の全面 AI 委譲と、それによる人間側の変容の一人称記録 | cases.md |

## 入場条件と境界(2026-08-20)

- **規模の大きさ単独はエッジではない**。how が常識外で、なぜそうしたか・何が起きたかが本人の言葉で読めること。初日の観測から: **自然発生の端**(実践者が自分の目的で強度を上げた結果)を優先し、**製造された端**(順位表・予算消化圧・ネタ作りが端を目的化させたもの)は載せる場合その旨を明記する
- **desire-frontier との境界**: desire は「AI に頼みたいことが尽きた後」の需要側(欲望・虚無)を観測する。edge は「常識外のやり方」でいま起きていることとその学びを扱う。崩壊系の証言が枯渇型(頼みたいことが尽きた)なら desire-frontier の testimonies へ回す
- 新ツール紹介・ベンチマーク・平均的な活用 Tips は対象外。有名事例の再確認(裏付け)も成果ではない

## 観測ループ

daily-research の `edge` line が毎日(daily = true、daily-research ADR-0013)この repo を cwd に外部観測し、事例を物語として解説するレポートを Obsidian vault へ出す。発見の台帳への還元(cases.md / reading-list.md / README)は運用者が手動 ingest で行う。良い事例が無い日は「なし」と短く書いてよい(発見ノルマなし)。
